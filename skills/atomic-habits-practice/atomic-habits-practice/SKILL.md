# 掌控习惯实践转化 Skill

## R - Source Grounding

This skill distills the actionable habit-design mechanisms from 《掌控习惯》:

- Habits run through cue, craving, response, and reward.
- Build good habits by making them obvious, attractive, easy, and satisfying.
- Break bad habits by making them invisible, unattractive, difficult, and unsatisfying.
- Identity change is stabilized by repeated evidence: every action is a vote for the kind of person the user wants to become.
- Systems beat isolated goals; tracking and recovery rules protect continuity.

## I - Interpretation

Treat a habit request as a behavior-design problem, not a motivation problem. The agent should identify the loop that currently exists, choose the smallest repeated behavior that can cast evidence for the desired identity, and reshape the user's environment so the desired behavior becomes easier than the competing behavior. The method is deliberately concrete: define when and where the action happens, stack it after an existing routine, reduce the first move to two minutes, add immediate satisfaction, and set a recovery rule for missed days.

## A1 - Application Examples

Book-backed examples include implementation intentions, habit stacking, environment design, the two-minute rule, habit tracking, and accountability contracts. When no personal context is provided, use a synthetic rehearsal and mark assumptions explicitly.

Example pattern:

Input: "I want to read more but keep scrolling at night."
Output: identity target, current loop, redesigned cue, stacked micro-habit, friction for scrolling, immediate reward, tracking rule, and relapse recovery plan.

## A2 - Future Trigger

Use this skill when the user asks how to build, fix, restart, track, or break a repeated behavior. Language signals include: "I keep failing to...", "help me build a habit", "I want to stop...", "make this easier to do daily", "design my environment", "habit tracker", "never miss twice", "identity-based habit", and "two-minute rule".

Do not use it for a one-time decision, emotional support without behavior design, medical addiction treatment, or broad life strategy where no repeated behavior is named.

## E - Execution

1. Define the target identity and behavior.
   - Ask: "What kind of person would reliably do this?"
   - Convert the identity into one observable repeated action.
   - Output: identity statement and minimum viable behavior.

2. Map the current or desired loop.
   - For good habits: cue, craving, response, reward.
   - For bad habits: trigger, hidden payoff, current response, delayed cost.
   - If any field is missing, ask one focused question or mark it as an assumption.

3. Apply the Four Laws.
   - Obvious: implementation intention, habit stacking, visual cue, environment placement.
   - Attractive: pair with something desired, use social proof or identity language.
   - Easy: reduce friction, use the two-minute starter, prepare the environment.
   - Satisfying: immediate reward, visual tracking, celebration, accountability.

4. For bad habits, invert the laws.
   - Invisible: remove cues.
   - Unattractive: reframe the real cost and false reward.
   - Difficult: add friction, blocks, commitments, or distance.
   - Unsatisfying: accountability or immediate consequence.

5. Add tracking and recovery.
   - Choose one behavior metric, one cadence, and one visible tracker.
   - Use "never miss twice" as the recovery rule.
   - Warn if the metric may distort the real goal.

6. Deliver a compact operating plan.
   - Include: identity, loop map, first two-minute action, environment changes, tracker, recovery rule, and one-week review prompt.

## B - Boundary

- Do not promise permanent transformation from one plan.
- Do not treat tracking as the goal; measure behavior only insofar as it supports the identity.
- Do not use this for clinical addiction, eating disorders, severe mental health issues, or medical behavior change without professional support.
- Avoid over-optimizing habits that need reflection, creativity, or periodic strategy changes.
- If the user has repeated failures, reduce scope before adding willpower.
